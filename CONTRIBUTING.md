# Contributing

Corrections should make the reference safer, more accurate, and easier to use under real operational conditions.

## Command quality

- Verify commands against the target distribution and current manual pages.
- State when a command is specific to Debian/Ubuntu, RHEL-family systems, a particular service, or a specific tool.
- Explain required privileges and expected side effects.
- Prefer inspect-first workflows before actions that change system state.
- Distinguish standard administration tasks from authorized penetration-testing workflows.
- Use reserved/example domains and lab IPs in demonstrations.

## Documentation quality

- Keep each entry task-oriented: purpose, use case, command, and important caveats.
- Explain non-obvious flags.
- Avoid presenting risky commands as universally safe.
- Retain links to authoritative documentation where available.

## Privacy and safety

Do not commit credentials, private keys, tokens, client details, or real engagement artifacts. Only add offensive-security procedures intended for systems under explicit authorization.
